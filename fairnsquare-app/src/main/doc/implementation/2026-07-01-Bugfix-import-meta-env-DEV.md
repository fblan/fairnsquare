# Bugfix: Replace `import.meta.env.DEV` with `LAUNCH_MODE` global

## What, Why and Constraints

Replaced `import.meta.env.DEV` in `Home.svelte` with `LAUNCH_MODE === 'DEVELOPMENT'`.

**Root cause:** The Home page component used `{#if import.meta.env.DEV}` to gate a dev-tools section. `import.meta.env` is a Vite-specific API; the Quarkus Web Bundler uses esbuild, which does not define `import.meta.env`. At runtime, `import.meta.env` was `undefined`, so accessing `.DEV` threw a `TypeError: Cannot read properties of undefined (reading 'DEV')`. This exception occurred during `Home2`'s render function, which caused the Router's branch effect to fail silently — resulting in a completely blank page (no route content ever displayed, only comment anchors in the DOM).

**Constraints:**
- esbuild's `define` map (auto-generated by `quarkus-web-bundler`) injects `LAUNCH_MODE` as a string literal at build time (`'DEVELOPMENT'`, `'TEST'`, or `'PRODUCTION'`), matching the Quarkus launch mode. This is the correct replacement for `import.meta.env.DEV`.
- esbuild evaluates `LAUNCH_MODE === 'DEVELOPMENT'` to `true` or `false` at compile time and tree-shakes the dead branch in production builds.

## How

### Files modified

- **`src/main/resources/web/app/routes/Home.svelte`** — Changed `{#if import.meta.env.DEV}` to `{#if LAUNCH_MODE === 'DEVELOPMENT'}` (line 198). This is the only occurrence of `import.meta.env` in the entire frontend source.

### Files created

- **`src/main/resources/web/app/env.d.ts`** — TypeScript ambient declaration for the `LAUNCH_MODE` esbuild global, so IDEs do not report it as an undeclared variable. Declares `LAUNCH_MODE: 'DEVELOPMENT' | 'TEST' | 'PRODUCTION'`.

## Tests

Manual verification:
- Quarkus dev mode hot-reloads after the edit; the rebuilt bundle at line 12217 now contains `if (true) $$render(consequent_3)` — esbuild replaced `LAUNCH_MODE === 'DEVELOPMENT'` with the literal `true`, confirming the define is active.
- No `import.meta.env` occurrences remain in the output bundle (previously 1).
- The Home page now renders correctly: the Router's branch effect can run `Home2` without throwing, and route content appears at `localhost:8080`.
